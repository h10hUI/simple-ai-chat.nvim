# simple-ai-chat.nvim: `@cmd` コンテキスト（外部コマンド出力の添付）仕様

## 目的

ユーザーが指定した外部コマンドの実行結果（`git diff` やテスト結果など）をコンテキストとして AI に渡せるようにする。

AI 自身にコマンドを実行させる（tool use）ことは行わない。Deno はリクエスト毎に起動・終了する構成で、ツール呼び出しの往復・承認 UI・`[DONE]` 区切りのテキストストリームに構造化イベントを載せる拡張が必要になるため、スコープ外とする。AI がコマンド出力を必要とする場合は、システムプロンプトでユーザーに `@cmd` での実行を依頼させる。

## 変更不要な箇所

- `deno/*`：コマンドは Lua 側で実行し、結果を既存の `<context ...>` ブロックとしてプロンプトに埋め込むだけ。プロトコル（stdin JSON / stdout ストリーム / `[DONE]`）は変えない。
- Deno の権限（`--allow-net` など）：コマンド実行は Neovim 側で行うため影響しない。

## 設計

### 記法

| 指定 | 内容 |
| --- | --- |
| `` @cmd:`<command>` `` | `<command>` を `sh -c` で実行し、stdout / stderr を添付する。空白を含むコマンドはこの形式 |
| `@cmd:<word>` | 空白を含まない単純なコマンド（例: `@cmd:ls`） |

例:

```text
@cmd:`git diff --staged` このコミットメッセージを考えて
@cmd:`deno test` 失敗しているテストを直して
```

### 実行仕様

- 実行はプロンプト送信時（`context.build_user_content` 内）に同期的に行う。
- カレントディレクトリは Neovim の cwd。
- 実行には `jobstart()` + `jobwait()` を使う（Neovim 0.9 でも動作する。`vim.system()` は 0.10 以降のため使わない）。
- タイムアウトは 10 秒。超過したらジョブを停止し、その時点までの出力に `[timeout after 10s]` を付ける。
- 出力は stdout と stderr を合わせて最大 100,000 バイト。超過分は切り捨て、末尾に `[truncated]` を付ける。
- 終了コードが 0 以外の場合は、出力の末尾に `[exit code: N]` を付ける。
- 起動に失敗した場合は `[Error running command: <command>]` を本文にする（`@file:` の読み込みエラーと同じ扱い）。

### 展開形式

他のコンテキストタイプと同じく、プロンプト先頭に `<context>` ブロックとして付与する。

````text
<context @cmd:`git diff --staged`>
```sh:git diff --staged
<出力>
```

<元のプロンプト>
````

### チャットウィンドウでの表示

コマンドの出力はチャット出力ペインにも表示する。`**You**:` のプロンプト原文の直後、モデル名ヘッダ（`**<model>**:`）の前に、`─── $ <command>` のヘッダ行に続けて、コマンドの出力をフェンスで囲まずそのまま追記し、`───` のフッタ行で閉じる。複数実行したときもブロックの区切りが分かる（Markdown シンタックスがコマンド出力中の ``` や `#` 等で崩れるのを避けるため）。API に送るプロンプトは変更せず、従来どおりフェンス付きのまま。

````text
**You**:

@cmd:`git diff --staged` コミットメッセージを考えて

─── $ git diff --staged
<出力>
───

**claude-sonnet-4-6**:
````

- 表示するのは `@cmd` の出力のみ。`@buf` / `@file:` など他のコンテキストは従来どおり表示しない。
- 表示内容は送信内容のフェンス内本文と同一（切り詰め・`[exit code: N]` などの注記を含む）。フェンス（` ```sh:<command> `）は表示せず、代わりに `─── $ <command>` を 1 行目、`───` を最終行に置く。罫線は Box Drawing 文字（`─`）を使い、Markdown の `---`（水平線／見出し化）は避ける。`@cmd` が複数あるときは、トークンの出現順にブロックを並べ、ブロック間は空行 1 行で区切る。
- 実行はプロンプト送信時に 1 回だけ。表示用と送信用で二重に実行しない。

### スティッキー

`/pin` の対象外とする。スティッキーは送信のたびに再実行されるため、副作用のあるコマンドが意図せず繰り返し走る恐れがある。`/pin @cmd:...` はエラーメッセージを出して無視する。

### セキュリティ

- 実行されるのはユーザーがプロンプトに書いたコマンドのみ。AI の応答に含まれるコマンドは自動実行しない。
- 確認ダイアログは出さない（送信 = 実行の意思表示）。

### システムプロンプト

`BASE_SYSTEM`（`lua/ai-chat/chat.lua`）に次の指示を追加する。

```text
コマンドの実行結果（git diff、テスト結果、ログなど）が回答に必要なときは、自分で実行しようとせず、ユーザーに実行を依頼してください。依頼するときは、次の形式でコマンドを示してください。

  @cmd:`<command>`

ユーザーがこれをプロンプトに含めて送信すると、実行結果があなたに渡されます。
```

## 実装

### `lua/ai-chat/context.lua`

- `extract_tokens`：`kind = "cmd"` を追加する。バッククォート形式を先に走査し、次に `@cmd:(%S+)`（先頭が `` ` `` のものは除く）を走査する。`key` は元の記法（`` @cmd:`git diff` `` / `@cmd:ls`）。
- `context_cmd(command)`：上記の実行仕様に従って実行し、`fence("sh", command, output)` を返す。
- `build_user_content`：`t.kind == "cmd"` の分岐を追加する。戻り値を `(content, cmd_blocks)` にし、`cmd_blocks` は `─── $ <command>\n<出力本文>\n───`（フェンスなし文字列）の配列とする。`context_cmd` はフェンス付き文字列と本文の 2 値を返す。

### `lua/ai-chat/commands.lua`

- `handlers.pin`：`@cmd:` で始まるトークンは追加せず、`[ERROR] @cmd cannot be pinned` を出力する。

### `lua/ai-chat/chat.lua`

- `BASE_SYSTEM` に上記の指示を追加する。
- 送信処理：`context.build_user_content` を出力ペインへの追記より先に呼び、`cmd_blocks` を `**You**:` のプロンプト原文の後ろ・モデル名ヘッダの前に追記する。

### ドキュメント

- `doc/spec.md` の「対応コンテキストタイプ」の表に `@cmd` を追記する。
- `README.md` のトークン表に `@cmd` を追記する。

## 決定事項

- AI によるコマンド自動実行（tool use）は行わない。
- コマンド出力はプロンプトへ埋め込み、同じ内容を出力ペインにも表示する。
- `@cmd` はスティッキー非対応。
